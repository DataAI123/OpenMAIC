# 完整多租户实施计划（批次 17–24）

## Context

`ENTERPRISE_REFACTOR_PLAN.md` §10 把「完整多租户」定义为两件事：

1. **资源边界** — 所有资源表、索引、缓存键、后台任务、文件和资产引用都落实租户边界；
2. **生命周期** — 支持成员与租户的生命周期管理。

「完整 RBAC」批次 14–16 已完成（权限矩阵、`withTenantPermission`、`tenant-admin.ts`、角色审计、三条 `/api/tenant/*` 路由、middleware 精确放行）。当前阻塞点与缺口已核实：

- **会话租户上下文缺失（核心阻塞）**：[session.ts](file:///d:/AI_APP/openmaic/lib/server/auth/session.ts) 在 SQL 里硬编码 `m.tenant_id = 'default'`，无法表达非默认租户；[identity.ts](file:///d:/AI_APP/openmaic/lib/server/auth/identity.ts) 首登固定加入 `'default'`；[usage-attribution.ts](file:///d:/AI_APP/openmaic/lib/server/usage-attribution.ts) 把 `user:` owner 固定映射到 `DEFAULT_TENANT`。
- **资源表无租户维度**：仅 `stage_meta`（迁移 0001）与 file-backed 的 classroom/job（`ownerId + tenantId`）具备租户维度；`agent_sessions`、`document_folders`、`document_stages`、`asset_entries`、`document_asset_refs`、`owner_material`、`export_render_job_owners` 只有 `owner_id`/`principal`。同一用户跨租户时 owner id 相同，构成跨租户泄漏面。
- **生命周期不完整**：只能「授予/变更/移除角色」（`assignTenantRole` 已能 upsert 新成员、`revokeTenantMembership` 能删除），**没有**租户创建/改名/停用/启用，**没有**成员 suspend/resume、自助退出，也没有"我的租户/切换活跃租户"。

目标产出：一个可运行的、失败关闭的完整多租户实现，legacy 模式行为不变，OIDC 模式下租户边界覆盖全部已开通业务路由，并具备租户/成员生命周期管理能力。

## 设计不变量（贯穿所有批次）

1. **租户上下文只来自服务端**：由 `auth_sessions.active_tenant_id`（DB 会话）解析，并按活跃 `tenant_memberships` 逐请求校验。绝不来自请求头、cookie 或请求体。
2. **失败关闭**：`active_tenant_id` 为空、成员资格非 active、或租户非 active → 业务路由返回 `403 TENANT_REQUIRED`（或既有 `LOGIN_REQUIRED` 语义），**绝不回退 `default`**。
3. **legacy 模式不变**：`anon:` owner 无租户；`usage-attribution` 的 legacy 分支保持现状。
4. **资源边界**：资源行携带 `tenant_id`；每个 owner 作用域查询同时约束租户；跨租户一律 `404`，不泄露存在性。
5. **生命周期操作**：单事务 + 按租户 `pg_advisory_xact_lock` + 审计 + 权限/秩守卫，复用 [tenant-admin.ts](file:///d:/AI_APP/openmaic/lib/server/auth/tenant-admin.ts) 的 `withClient` / `lockTenantRoleMutations` / `TenantAdminError` 模式，不新建平行模块。
6. 不重建 OIDC 配置/会话/路由目录；不把 OIDC `sub`/email 当授权主体；不在登录回调自动合并匿名数据。
